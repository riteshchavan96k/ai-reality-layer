## Real downstream AI product gap
The real claim-only API and Step235 client gate can issue `bounded_supported` from independently captured original-source text, but do **not yet provide that unique verified excerpt to an authorized client**. An optional neural semantic check therefore cannot be bound to the **same captured original-source statement**, and cannot help prevent a misleading neural result from being treated as stronger evidence. Build the *least-authority*, auditable integration that allows an AI application to inspect the actual verified statement and optionally **veto** an otherwise bounded supported decision. No model decision can ever promote an unsupported claim.

## Scoped engineering deliverables
1. Extend the existing authenticated `POST /api/v1/reality-state/claim` response with an **optional, strictly bounded `source_evidence`** containing exactly the server-selected complete original-source unit, SHA256 of that exact UTF-8 text, and the identical trusted source capture digest and UTC observation time. Emit it **only after** the existing Reality State pipeline confirms a unique standalone, nonquoted, no-counterstatement original-source observation and a bounded supported/contradicted relationship. Otherwise never emit text. No arbitrary document echo, no new source request, no API authentication changes.
2. Build a separate **opt-in developer-callable AI client adapter** that makes exactly **one** authenticated call, independently interprets the original Step235 Reality State guard, validates the handoff evidence identity/hash/capture/time and request source, then asks an injected **real or test** NLI model `predict(premise=verified_text, hypothesis=original_claim_text)`. Strictly validate bounded 3-class scores, label and truth/authority flags. A neural result can **only retain an already-bounded-supported** decision when it predicts `entailment`. Any neutral, contradiction, missing model, missing/tampered evidence, error or mismatched output **abstains**. If the source API already abstains or contradicts, it must never call the model to override that finding. A model entailment can **never** create supported if the source gate was not already supported.
3. Keep existing Step235 `check_claim_with_api` signatures and behavior. No production backend ML package, default model registry, Docker change or downloaded model in ordinary API runtime. Client owns safe authenticated transport and supplied neural model, with explicit research/developer opt-in.
4. Add adversarial regression tests: real authenticated local FastAPI, single source reader observation, no evidence leaking on insufficient/forged/unallowed cases, capture/sha/time mismatch, changed claim/source, large excerpts, unsupported API state, model neutral/contradict/entail, unavailable/malformed outputs, wrong score labels, model exception, no double HTTP/read, secret/excerpt-safe logs, no hidden semantic promotion.
5. New **14th independent GitHub CI workflow** must execute pinned actual Hugging Face ONNX Transformer with actual Python.org observed original source through real authenticated local FastAPI, bound handoff plus client veto logic. Reproduce ordinary backend tests and historical 13 workflows on exact final merged-main SHA before calling Step240 complete.
6. Document all epistemic ceilings: external SNLI benchmark cannot certify source truth; optional neural veto may increase false abstentions; no measured real-domain improvement, independent fact accuracy, production semantic authorization, publisher-signed provenance, or public deployment claimed.
