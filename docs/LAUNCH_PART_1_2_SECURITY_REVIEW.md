## 4. Practical owner-only verification sequence (do not post sensitive values)

1. **GitHub → Settings → Secrets and variables / Deploy keys / Webhooks / Installed GitHub Apps / Collaborators:** review *actual current pages* with the repo owner. Record only a private redacted count, trusted purpose and whether unknown access was revoked. Confirm connector access is intentional.
2. **GitHub → Security → Secret scanning / Dependabot alerts:** inspect all severity filters and open/closed views; note whether alerts are enabled. Privately triage real alerts, verify patch availability and risk. Zero displayed alerts is evidence only for that enabled source and instant, not universal clearance.
3. **GitHub → Actions → Caches:** independently verify current cache list/scope. Don't download untrusted cached content into an operator workstation unnecessarily. Make a documented retention or invalidation decision. Don't destroy caches or force-rewrite Git history merely because full forensic examination is impossible.
4. **External credentials:** review each provider's portal, API tokens, scopes, last-used indications and old environments, including any previously used GitHub personal tokens. If a live credential was exposed, immediately revoke/rotate via its provider, assess usage, and verify no live secret remains; store evidence privately.
5. **Licensing and provenance:** evaluate only the actual early-alpha shipping/runtime artifact plus any distributed SDK; distinguish dev/optional benchmarks from Docker production. Record permitted use and required notices. Do not publish proprietary ownership evidence, client agreements, or provider secrets.
6. **Record a bounded explicit decision** by the owner in private operational records: date, reviewed surfaces, material findings, mitigations, unresolved exclusions, permitted first-alpha scope, and whether further access is authorized. Public PR comments may state only 'reviewed / action pending / cleared with limitations', never sensitive specifics.
