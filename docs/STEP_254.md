## New scoped capability
Previous Step253 answered one release-date question using an independently captured Python.org field, an optional real `google/flan-t5-small` proposer and an independent deterministic acceptance gate. The model did not improve coverage over a deterministic parser. Step254 tests that observation on **three distinct genuine official-source release pages** and adds a **second historical factual attribute**, whether each version was explicitly described as a stable release at publication time. No assertion is made about the version's *current* security/support status.

- Three official publisher pages selected and reviewed before implementation: [Python 3.11.0](https://www.python.org/downloads/release/python-3110/), [Python 3.12.0](https://www.python.org/downloads/release/python-3120/), [Python 3.13.0](https://www.python.org/downloads/release/python-3130/).
- Frozen six-case `backend/evaluation_fixtures/step254_real_official_answer_v1.json`: each page yields one date and one historical release-type question. Gold dates: **2022-10-24**, **2023-10-02**, **2024-10-07**, respectively. Each official release page explicitly describes itself as a **stable release**. Labels were hand-reviewed against official webpages, not automatically generated by a model, but external professional independent label-review and sampling representativeness are NOT proven.
- An additional authenticated source-observation API `POST /api/v1/reality-state/extract/release-status` performs exactly one operator-allowlisted source HTTPS fetch under existing DNS/IP/TLS rules, binds exact entity/question/URL, requires a unique document heading and a unique standalone nearby historical `This is the stable release of Python ...` statement, excludes matching HTML-quoted units, verifies capture timestamps and emits canonical quote/capture/hash provenance. The API itself runs no model, has no general truth authority and never returns partial receipts on failure.
- The strictly typed defensive client `check_release_status_with_model` independently re-parses the original observed quote, hashes, freshness and request-binding digest, and provides a narrow prompt to optional pinned CPU FLAN-T5 model `extract_status`. Any output besides `stable` or `stable release`, or source ambiguity, malformed response or authentication failure, MUST abstain without citation. No LLM output may widen the original-source authority.
- The existing date service and Step253 client are unmodified, preserving prior functionality. No external deployment, broad arbitrary web retrieval, current security-support classification, or general-domain answer interpretation is established.

## Model-value evaluation and experimental honesty
- `backend/app/evaluation/step254_live_model_value.py --live` measures **all six predeclared source cases** with genuine pinned FLAN-T5 CPU inference and real authenticated single-capture official Python.org HTTPS retrieval. Hardcoded independent gold map prevents silent manifest relabeling; all cases remain in the denominator.
- Report deterministic parse accuracy versus model *verified-answer* coverage, model abstentions, false support count, release-type success count, and observed end-to-end latency. No unsupported answer may be reported as correct. Model must genuinely execute on all cases, and successfully complete at least one new release-type answer.
- Deterministic baseline is explicitly expected to handle all six cases; the LLM's **incremental accuracy advantage is not assumed**. A negative or zero gain is a meaningful and reportable result, indicating future need for stronger models, more semantic sources or improved evidence extraction before GPU expansion.
- The sample is small, selected and official-only; no statistically generalizable source-truth accuracy, publisher authorship authentication, multi-publisher corroboration or real-world reliability percentage is claimed.
- Adversarial tests cover three versions and both fact types, hallucinated/model-swapped status, altered/duplicated/ambiguous source, wrong bearer/URL, stale capture, forged quote hashes, unsupported question, malicious extras and no opt-in model downloads.

## First real PR-head experimental results — fixed six-case subset

The first actual six-case genuine-source/genuine-LLM workflow reported:
`deterministic_baseline_correct=6/6`,
`model_supported_correct=4/6`,
`model_abstained=2/6`,
`model_false_supported=0/6`,
`model_release_type_correct=1/3`,
`net_model_coverage_gain_over_deterministic=-2`.
Its observed mean *warm-model* HTTPS request + model inference latency was about 184 ms;
this omits model download/load time and cannot be extrapolated to production traffic.
**No evidence of neural-model superiority in this limited distribution** was observed;
model outputs are not used to widen deterministic evidence permissions. This is a
meaningful negative model-value result and informs selection of stronger models
or better prompts only on future **held-out** data, not post-hoc optimizing this
frozen evaluation set. No cloud GPU cost or authorization occurred.
